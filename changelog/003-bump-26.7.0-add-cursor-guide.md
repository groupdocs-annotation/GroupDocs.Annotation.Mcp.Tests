# Target 26.7.0, add Cursor guide, fix leftover Signature prose

## What changed

- Bumped the package-under-test from `26.5.0` to `26.7.0` everywhere it is a
  live pin: `Directory.Build.props` (`McpPackageVersion` default),
  `.github/workflows/integration.yml` (input default + `MCP_PACKAGE_VERSION`
  fallback), `examples/*.json`, `how-to/01–06`, `docker-scripts/*`, README, and
  AGENTS. Historical changelog entries (001, 002) are left untouched.
- Added [`how-to/07-use-with-cursor.md`](../how-to/07-use-with-cursor.md) plus
  [`examples/cursor-mcp.json`](../examples/cursor-mcp.json) — the standard Cursor
  onboarding guide (dnx / Windows `dotnet.exe` cached-DLL SSL workaround / Docker),
  adapted for the 10 annotation tools and Annotation's eval-mode watermark
  behaviour. Linked from `how-to/README.md`.
- Fixed leftover **Signature-era prose** in `how-to/README.md` "Common context":
  it claimed the wire tools were `sign` and `verify` and that `verify` needs a
  license to `Save()`. Replaced with the real 10 annotation wire names and
  Annotation's actual eval-mode behaviour (read-only tools unaffected; writers
  and preview still run but may watermark output).

## Why

Keep the integration suite pinned to the current release and give Cursor users a
first-class onboarding path matching the other MCP products. The Signature prose
was a clone-substitution miss (Pitfall #1/#5).

## Migration / impact

Tests-repo-only. `ToolDiscoveryTests` already asserts the 10-tool surface, which
is unchanged. Integration tests run against the published `26.7.0` NuGet once it
is released.
